# 06 – Create a project

**Goal:** Create a persistent Project to help coordinate the remaining voting issues.

## Key terms

- **Repository (repo):** a project folder whose full history is tracked by Git and hosted on GitHub.
- **Branch:** a separate line of work inside a repo. `main` is the shared, "official" version. Changes happen on other branches so `main` stays stable.
- **Repository coding session:** the conversation you started in task 01, attached to a repository and its working copy for a piece of work.
- **Persistent Project:** a separate, ongoing space in the app for coordinating work and sessions. Adding a repository to the app does not by itself create a persistent Project.

## Steps

1. In the GitHub Copilot app, create a persistent Project for your workshop. Keep it separate from the repository coding session you started in task 01.
2. Tell the Project about your workshop repository and the two open issues from task 03. Try:
   ```text
   I'm working on the canteen menu voting workshop in my repository [replace with your repository name or URL]. The "Change your vote" and "Display results" issues remain open. Read them, propose an order for the work, and explain how you can coordinate a repository coding session for each issue. Don't change any files yet.
   ```
3. Check the proposed order against the issues. Changing a vote comes before displaying results in this workshop, so results can include vote changes. Ask the Project to adjust its plan if needed.
4. Compare the Project conversation with your task 01 repository session: the Project coordinates work across sessions; the repository session works with a repository and its working copy.

## Done when

- [ ] You created a persistent Project for the workshop
- [ ] You can explain the difference between the Project and a repository coding session
- [ ] The Project has proposed an order for the remaining issues
